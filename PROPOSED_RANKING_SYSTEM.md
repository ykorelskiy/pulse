# Архитектурное предложение: Переход на систему «Позитивного ИИ-Ранжирования» новостей

Этот документ предназначен для аудита архитектуры отбора новостей в проекте сатирического Telegram-канала «Пульс дня».

---

## 1. Текущая реализация (Негативная фильтрация)

На данный момент система отбора Топ-10 новостей из кандидатского пула (50-100 новостей, собранных по RSS и из Telegram-каналов) построена на принципах **негативной фильтрации**.

### Механика работы
1. Все собранные новости отправляются в LLM (Gemini).
2. В системном промпте задан огромный блок `stop_words` и запретов:
   - Запрет на военные сводки, БПЛА, жертвы, трагедии.
   - Запрет на обзоры видеоигр (Steam, трейлеры) и железа (SSD, шины).
   - Запрет на сухую политику и корпоративный PR (пресс-релизы, назначения, экскурсии).
3. Нейросети дается команда: "Выбери 10 новостей, избегая тем из запрещенного списка, и отдавая приоритет позитивному абсурду".
4. Нейросеть возвращает массив из 10 ID новостей и переводит их заголовки на русский язык. Оставшиеся 40+ новостей остаются на языке оригинала (если это зарубежные источники) и не получают никаких оценок, просто попадая в общую свалку (Раздел 2 — ТОП-50).

### Проблемы текущего подхода
- **Бесконечное расширение бан-листа**: Невозможно предугадать все скучные или мусорные темы. Сегодня проскочила новость «Президент Колумбии ушел в отставку», завтра — «Урожай свеклы вырос на 5%», послезавтра — «Редакция СМИ провела экскурсию для школьников». 
- **Эффект "черного ящика"**: Нейросеть выдает готовый ТОП-10, и мы не понимаем, почему она выбрала именно эти новости, а не другие. Нет прозрачной метрики.
- **Проблема непереведенных "хвостов"**: Поскольку обрабатываются только 10 избранных элементов, остальные новости в расширенных подборках остаются непереведенными.

---

## 2. Предлагаемая реализация (Система Позитивного Ранжирования)

Предлагается фундаментально сменить парадигму с **«отсечения плохого»** на **«математическое взвешивание хорошего»**. Нейросеть будет выступать не цензором, а жюри, выставляющим баллы каждой новости из пула.

### Новая механика работы
В LLM отправляется весь пул кандидатов (до 100 новостей). Нейросеть обязана вернуть JSON-массив, где для **КАЖДОЙ** новости будут выставлены 4 оценки (от 1 до 5) и предоставлен литературный русский перевод заголовка.

#### Критерии оценки (от 1 до 5):
1. **Relevance (Релевантность)**: Насколько это событие вообще понятно и интересно массовому читателю из РФ/СНГ?
2. **Positivity (Позитивность)**: Насколько новость вызывает улыбку, смех и поднимает настроение? (Любая чернуха, политика, трагедии и скука жестко получают 1 балл).
3. **Virality (Виральность)**: Безумие / Абсурд / Вау-эффект. Насколько сильно читатель захочет переслать эту новость другу? (Например, "Индусы сушат шоссе вентиляторами" = 5 баллов).
4. **Significance (Масштаб)**: Насколько это глобальное, историческое или общенациональное позитивное событие (Олимпиада, праздники, крупные курьезы мирового масштаба).

#### Формула и сортировка
1. В Python-коде для каждой новости высчитывается `Total Score = Relevance + Positivity + Virality + Significance`.
2. Весь массив сортируется по убыванию `Total Score`.
3. **ТОП-10** (новости с максимальным баллом 15-20) формируют главную витрину (Раздел 1).
4. Оставшиеся элементы (уже переведенные на русский язык) уходят в Раздел 2.
5. Любые скучные корпоративные новости или мелкая бюрократия автоматически получат по 1-2 балла за Виральность и Позитивность, из-за чего математически упадут в самый низ списка и никогда не попадут в ТОП-10.

## 3. План перехода

1. **Обновление Промпта (`src/pulse/digest/llm.py`)**
   - Переписать инструкцию Gemini. Убрать гигантские списки запретов.
   - Внедрить описание 4 критериев (от 1 до 5).
   - Запросить строгий JSON-формат для 100% массива кандидатов:
     ```json
     [
       {
         "id": 1,
         "ru_headline": "Индийские дорожники сушат просевшее шоссе вентиляторами",
         "relevance": 4,
         "positivity": 5,
         "virality": 5,
         "significance": 2
       }
     ]
     ```

2. **Обновление логики процессинга (`src/pulse/digest/llm.py`)**
   - Парсинг JSON-ответа.
   - Вычисление суммы баллов.
   - Сортировка всего пула кандидатов.
   - Возврат отсортированного ТОП-10 и полного обновленного (и переведенного) списка ТОП-50.

3. **Обновление Fallback-механизма**
   - В случае падения API Gemini, Python-скрипт должен использовать локальный алгоритм.
   - Обязательный прогон всех непереведенных строк через библиотеку автоперевода (например, `deep_translator` / `GoogleTranslator`), чтобы в Разделе 2 не осталось английских символов.
   - Базовая эвристическая раздача баллов на основе ключевых слов (как резервный вариант).

4. **Тестирование**
   - Прогон алгоритма на существующей базе `news_items` за последние сутки.
   - Проверка, что в ТОП-10 попали только новости с высоким виральным потенциалом, а во 2-м разделе (ТОП-50) 100% заголовков переведены на русский язык.
