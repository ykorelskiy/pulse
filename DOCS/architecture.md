# Архитектура проекта Pulse (Assisted Mode)

## 1. Обзор системы

Проект **Pulse** — ежедневный дайджест-плакат в Telegram и веб-архиве, работающий в гибридном режиме **Assisted Mode**:
- **Автоматизация бэкенда (90%):** Сбор RSS-новостей, агрегация слов читателей через Telegram-бота, генерация короткого бриф-контекста для автора, приём готовой работы, публикация в Telegram-канал, подведение итогов разгадок, веб-архив и приём заказов.
- **Авторская генерация (10%):** Автор получает короткий бриф в Telegram-бот, генерирует иллюстрацию в ChatGPT, при необходимости вносит поправки и загружает постер обратно в бот.

```
[RSS-ленты] ──> [Сборщик новостей (M2)] ──┐
                                          ├──> [Формирователь брифа (M3)] ──> [Telegram-Бот]
[Telegram-Бот] ──> [Сбор слов (M1)] ──────┘                                         │
                                                                                    ▼
                                                                        [Автор: рисует в ChatGPT]
                                                                                    │
                                                                                    ▼
[Канал Telegram] <── [Публикатор (M7)] <── [Хранилище R2 (M5)] <── [Загрузка постера (M6)]
       │
       ▼
[Дискуссионная группа: Разгадки (M8)] ──> [Подведение итогов (M8)] ──> [Победитель в следующий бриф]
```

## 2. Модули системы

| Модуль | Компонент | Назначение |
|---|---|---|
| **M0** | `pulse.config`, `pulse.db` | Конфигурация (`pydantic-settings`), репозитории Supabase, логгер |
| **M1** | `pulse.bot` | Бот сбора слов от читателей (лимит 1 слово в 24 часа) |
| **M2** | `pulse.sources` | Сбор RSS-новостей и сохранение в Supabase |
| **M3** | `pulse.digest`, `pulse.briefsmith` | Сборка 5 ключевых новостных фраз (прямолинейно, по указанию пользователя) |
| **M5** | `pulse.intake.storage` | Загрузка постера в Cloudflare R2 + генерация 2K веб-версии (Pillow) |
| **M6** | `pulse.bot.handlers` | FSM согласования: отправка брифа автору (`@anta9onist`) и прием постера |
| **M7** | `pulse.publisher` | Публикация готового выпуска в Telegram-канал с подписью |
| **M8** | `pulse.engagement` | Приём разгадок, подсчёт голосов, выбор победителя дня |
| **M9** | `pulse.orders` | Приём и обработка заявок на персональные заказные плакаты |
| **M10** | `pulse.jobs` | Автоматические задачи (Cron GitHub Actions) |

> [!NOTE]
> **Указание пользователя (2026-08-07):**
> 1. Автор Telegram: `@anta9onist`.
> 2. Сняты принудительные запреты на имена политиков и метафоры. Бриф формируется прямолинейно ("как есть").
> 3. Модуль M3 извлекает ровно 5 ключевых новостных фраз/сочетаний дня.

## 3. Схема базы данных (Supabase PostgreSQL)

Все пользовательские таблицы содержат обязательное nullable-поле `tenant_id uuid` для будущей B2B-изоляции.

1. **`sources`**: RSS-источники новостей.
2. **`news_items`**: Собранные новости (`url` UNIQUE).
3. **`users`**: Зарегистрированные пользователи Telegram-бота.
4. **`words`**: Присланные слова читателей (`user_id`, `word`, `created_at`).
5. **`issues`**: Выпуски плакатов дня (`date` UNIQUE, `status`: `draft|awaiting_image|ready|published|skipped`).
6. **`briefs_history`**: История сгенерированных брифов для автора.
7. **`guesses`**: Версии разгадок пользователей (`issue_id`, `text`, `votes`).
8. **`reserve_posters`**: Резервные плакаты на случай отсутствия автора.
9. **`orders`**: Заказы персональных плакатов (`status`, `amount`, `customer_tg`).
10. **`events`**: Аудит действий и событий системы.

## 4. Расписание автоматических задач (GitHub Actions / Cron)

- **`0 * * * *` (`collect.yml`)**: Ежечасный сбор новостей из RSS.
- **`0 15 * * *` (`daily.yml`)**: Сборка брифа дня в 18:00 МСК (15:00 UTC) и отправка автору в бот.
- **`50 20 * * *` (`winner.yml`)**: Подведение итогов разгадок дня в 23:50 МСК (20:50 UTC).
- **`0 0 * * *` (`keepalive.yml`)**: Пинг работоспособности сервиса.
