# ТЗ: Мультиплатформенная публикация — ВКонтакте, Instagram, LinkedIn

Расширение уже работающей связки «генерация → Telegram-канал → сайт» дополнительными каналами дистрибуции. Архитектурный принцип: единая точка одобрения (Модуль Д уже есть), после которой картинка расходится по всем включённым площадкам параллельно — не переделывать процесс согласования под каждую соцсеть отдельно.

---

## 1. Архитектурный принцип: слой «Publisher»

Вместо жёсткой привязки «одобрил → запостил в Telegram» вводится абстракция, аналогичная уже сделанному слою для image API (переключаемые провайдеры gpt-image-1 / Nano Banana):

```python
class Publisher(ABC):
    def publish(self, image_url: str, caption: str) -> PublishResult: ...
```

Реализации: `TelegramPublisher` (уже есть), `SitePublisher` (уже есть), `VKPublisher` (новый), `InstagramPublisher` (новый). LinkedIn — намеренно **без** класса-публикатора, см. раздел 4.

После нажатия «✅ Опубликовать» в Модуле Д оркестратор проходит по всем `platforms where enabled = true` и вызывает соответствующий Publisher. **Важно: сбой на одной площадке не должен блокировать остальные** — если, например, у Instagram истёк токен, Telegram и сайт всё равно публикуются, а сбойная площадка логируется и уходит на ручной ретрай.

---

## 2. Модель данных

```sql
create table platforms (
  id text primary key,             -- 'telegram' | 'site' | 'vk' | 'instagram'
  enabled boolean default true,
  caption_template text,           -- шаблон подписи под конкретную площадку (хэштеги, тон, ссылка на Telegram)
  publish_time time,               -- своё время публикации на площадку, не обязательно единое 18:00 для всех
  credentials_ref text             -- ссылка на секрет в .env/секрет-хранилище проекта, сам токен в БД не хранить
);

create table platform_posts (
  id uuid primary key default gen_random_uuid(),
  issue_id uuid references issues(id),
  platform_id text references platforms(id),
  post_url text,
  status text default 'pending',   -- pending | published | failed
  error text,
  published_at timestamptz
);
```

## 3. VK — публикация в сообщество (авто)

Технически проще Instagram, делается полностью через VK API, бесплатно.

**Настройка (разово, руками):**
1. Создать сообщество ВКонтакте (если ещё нет).
2. В настройках сообщества → Работа с API → создать ключ доступа сообщества с правом `wall`.

**Пайплайн публикации (2 шага, VK не даёт постить фото по прямой ссылке — сначала нужно загрузить в их хранилище):**
1. `photos.getWallUploadServer` → получить URL для загрузки → загрузить файл → `photos.saveWallPhoto` → получить `attachment id` (`photo<owner_id>_<photo_id>`).
2. `wall.post` с `owner_id = -<id_сообщества>`, `message = caption`, `attachments = <photo id из шага 1>`.

Лимиты не проблема при частоте 1 пост/сутки.

## 4. Instagram — публикация в бизнес-аккаунт (авто)

Здесь больше подготовительных шагов, но тоже без денег и без App Review при использовании только для собственного аккаунта.

**Настройка (разово, руками):**
1. Instagram-аккаунт должен быть переведён в **Business** или **Creator** и привязан к Facebook-странице, которой ты управляешь.
2. Создать приложение в Meta for Developers, добавить продукт **Instagram Graph API**.
3. Получить long-lived Page Access Token с правами `instagram_basic`, `instagram_content_publish`, `pages_show_list`. Для публикации только в свой аккаунт (не чужие) достаточно режима разработки приложения с твоим аккаунтом, добавленным как тестовый пользователь — полное App Review от Meta не требуется.

**Пайплайн публикации (2 шага, важное ограничение — картинка должна отдаваться по публичному HTTPS-URL, не файлом):**
1. `POST /{ig-user-id}/media` с параметрами `image_url` (публичная ссылка на уже сгенерированную и опубликованную картинку — например, тот же URL, что ушёл на сайт) и `caption` → получить `creation_id`.
2. `POST /{ig-user-id}/media_publish` с `creation_id` → пост опубликован.

Лимит — около 25 публикаций в сутки на бизнес-аккаунт, при частоте 1/сутки не актуально.

**Формат:** алгоритм Instagram сейчас сильно приоритизирует Reels перед статичными постами в ленте по охвату. Стоит рассмотреть отдельно (не обязательно к MVP этого расширения) короткий видео-тизер — панорамирование камеры по деталям готовой картинки 5-8 секунд — как отдельный, более нативный для площадки формат, генерируемый после основной картинки, а не вместо неё.

## 5. LinkedIn — намеренно без автопостинга

Ты сам сказал, что хочешь публиковать туда выборочно и вручную — под это не нужен `LinkedInPublisher`, а нужна просто удобная выгрузка:

- В Модуле Д при нажатии «Опубликовать» бот дополнительно присылает отдельным сообщением **«Экспорт для LinkedIn»**: сама картинка файлом + альтернативный вариант подписи, написанный в другом тоне.
- Тон для LinkedIn стоит сознательно сместить от мемного к «производственному» — например, вместо шутки о новости дня можно давать ракурс «как устроен процесс» (что легло в основу сегодняшней картинки, как работает конвейер и т.п.) — эта аудитория обычно лучше реагирует на контент о процессе создания продукта, чем на сырой мем без контекста.
- Публикуешь сам, когда решишь, что конкретный выпуск стоит внимания той аудитории.

## 6. Рекомендации по продвижению

- **Не копировать один и тот же пост на все площадки бездумно** — у каждой свой формат ожиданий: в Telegram и на сайте — как есть, в VK можно оставлять более длинную подпись со ссылками, в Instagram — короче + хэштеги, в LinkedIn — с рамкой про процесс, а не только результат.
- **Хэштеги в Instagram** — отдельное поле `caption_template` для этой площадки должно включать подобранный набор: смесь широких (юмор/AI/мемы) и нишевых RU-тегов; без них охват вне подписчиков будет околонулевым.
- **Первые недели — ручной посев в тематические сообщества VK** (юмор, IT, RU-мемы) — до появления органической аудитории это самый быстрый способ получить первый трафик, дороже по времени, но бесплатно по деньгам.
- **Механика разгадок как воронка между площадками** — в подписи к посту в VK/Instagram явно звать обсуждать и разгадывать именно в Telegram-группе (где уже есть голосование и приз «стать персонажем») — так остальные площадки работают как источник новых людей в основное комьюнити, а не как параллельная, никак не связанная лента.
- **Своё время публикации на площадку** (уже заложено полем `publish_time` в разделе 2) — у каждой соцсети свои часы пиковой активности аудитории, не обязательно публиковать везде ровно в 18:00.

---

## 7. Что не меняется

Модуль Д (итеративное согласование с админом) остаётся ровно тем же — одна точка одобрения на все площадки разом. Ничего в логике генерации картинки, ранжирования новостей или брифа этим расширением не затрагивается.
