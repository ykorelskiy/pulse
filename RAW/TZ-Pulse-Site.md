# ТЗ: Сайт «Пульс дня» — отрывной календарь

Документ для Antigravity. Версия 1.

Сайт-витрина проекта «Пульс дня»: каждый день в 20:00 (Europe/Moscow) публикуется
иллюстрация дня (создаётся вручную, загружается через Telegram-бота). Сайт показывает
её в виде отрывного календаря + сетку месяца с превью для навигации по архиву.

**Принцип работы над проектом: строго по шагам из §9, по одному шагу за раз,
с проверкой критериев приёмки перед переходом к следующему. Не объединять шаги.**

---

## 1. Общая архитектура

- **Бэкенд-логики нет.** Только Supabase:
  - **Storage** — картинки (оригинал + превью), папки по датам;
  - **Postgres** — одна таблица метаданных выпусков;
  - анонимный доступ **только на чтение** (RLS), запись — только бот через service key.
- **Фронтенд** — статический SPA: Vite + React + TypeScript. Никакого SSR на старте.
- **Деплой** — Vercel или Netlify (статика); Supabase у заказчика уже есть.
- **Бот** (уже существует, дорабатывается) — принимает картинку, генерирует превью,
  загружает в Storage, создаёт запись в таблице; в 20:00 ставит флаг публикации.
  Постинг в Telegram-канал — вне рамок этого ТЗ, уже работает.
- Топ-10 новостей приходит из существующей системы «Пульс дня» (см. отдельное ТЗ);
  на фазе 1 сайту нужна только картинка, поле под новости закладываем сразу (jsonb).

Таймзона всего проекта: **Europe/Moscow**. «День» выпуска определяется по ней.

---

## 2. Хранение картинок (Supabase Storage)

Бакет: `pulse-covers`, публичное чтение.

Структура путей (папки по датам):

```
pulse-covers/
  2026/
    08/
      08/
        cover.webp        — полный размер (длинная сторона <= 2048px)
        thumb-480.webp    — превью для листа на мобильных / OG-превью
        thumb-128.webp    — мини-превью для ячейки сетки месяца
```

Правила:
- **Превью генерирует бот при загрузке** (sharp для Node / Pillow для Python):
  3 файла, формат WebP, качество 80. Не полагаться на трансформации Supabase
  на лету — превью в ячейках календаря запрашиваются десятками за раз,
  пререндер дешевле и быстрее.
- Оригинал перед загрузкой: конвертация в WebP, ресайз до 2048px по длинной
  стороне, ориентир по весу ~500 КБ.
- Повторная загрузка картинки за тот же день — **перезапись** (upsert файлов
  и строки в таблице). Это штатный сценарий «исправил и перезалил».
- Кэширование: `cache-control: max-age=3600` (не immutable — возможна
  перезапись в течение дня).

## 3. Модель данных (Supabase Postgres)

```sql
create table site_issues (
  id uuid primary key default gen_random_uuid(),
  issue_date date not null unique,           -- день выпуска (Europe/Moscow)
  image_path text not null,                  -- '2026/08/08/cover.webp'
  thumb480_path text not null,
  thumb128_path text not null,
  title text,                                -- опционально: подпись/тема дня
  news jsonb,                                -- фаза 2: топ-10 [{tag, text, source_url}]
  published boolean not null default false,  -- true — виден на сайте
  published_at timestamptz,
  created_at timestamptz default now()
);

create index idx_site_issues_date on site_issues (issue_date desc);

alter table site_issues enable row level security;

-- Аноним видит только опубликованное
create policy "public read published"
  on site_issues for select
  using (published = true);
-- Запись/обновление — только сервисный ключ бота
-- (для anon никаких insert/update политик не создаём)
```

## 4. Доработка бота (загрузка и публикация)

1. **Приём картинки** (существующий диалог с ботом):
   - определить дату выпуска: по умолчанию «сегодня» (Europe/Moscow),
     с возможностью указать другую дату явно — подписью к картинке в формате
     `2026-08-08`. Нужно для дозагрузки пропущенных дней и подготовки наперёд;
   - сгенерировать 3 файла (см. §2), загрузить в Storage с upsert;
   - upsert строки в `site_issues` (`published = false` для будущих дат
     и для «сегодня до 20:00»);
   - ответить в чат подтверждением: превью + дата выпуска.
2. **Публикация в 20:00** (cron бота, уже существует для Telegram-канала):
   - `update site_issues set published = true, published_at = now()
      where issue_date = current_date and published = false;`
   - если картинки на сегодня нет — не публиковать, но прислать алерт
     владельцу в личку.
3. **Идемпотентность**: повторный запуск публикации ничего не ломает
   (условие `published = false`).

## 5. Фронтенд — структура страницы

Один экран, две зоны (desktop):

```
+----------------------------+--------------------------+
|  ОТРЫВНОЙ КАЛЕНДАРЬ        |  СЕТКА МЕСЯЦА            |
|  (левая зона, ~60%)        |  (правая зона, ~40%)     |
|                            |                          |
|  [перфорация/скоба]        |   <  Август 2026  >      |
|  8                         |  пн вт ср чт пт сб вс    |
|  АВГУСТА 2026, СУББОТА     |  [ячейки с превью        |
|  [иллюстрация дня]         |   thumb-128]             |
|  (клик -> полный размер)   |                          |
+----------------------------+--------------------------+
```

### 5.1 Отрывной календарь (левая зона)
- Визуальный стиль классического отрывного календаря: «перфорация» сверху,
  лёгкая тень «стопки листов» позади, слегка загнутый нижний угол.
- Контент листа:
  - крупное число дня;
  - месяц + год, день недели, номер недели в году;
  - **суббота, воскресенье и праздники — красным** (и число, и день недели);
  - иллюстрация дня (`thumb-480` на мобильных, `cover` на desktop);
  - клик/тап по иллюстрации — лайтбокс с полноразмерной картинкой
    (закрытие: крестик, Esc, клик по фону);
  - зарезервированное место под текстовый блок (топ-10 новостей, фаза 2) —
    сейчас пустое, вёрстка не должна «прыгать» при его появлении.
- **Анимация перелистывания** при смене дня: лист «отрывается» вверх
  (CSS transform + opacity, 300–400 мс). Без тяжёлых библиотек —
  framer-motion или чистый CSS. При `prefers-reduced-motion` — без анимации.

### 5.2 Сетка месяца (правая зона)
- Классическая сетка: заголовок «Месяц Год», стрелки ← → для листания месяцев,
  строка дней недели (пн–вс), недели строками.
- Ячейка дня, 4 состояния:
  - **есть опубликованный выпуск** → мини-превью `thumb-128` + число дня
    поверх; кликабельна;
  - **выпуска нет (прошлое)** → число на нейтральном фоне, приглушена,
    некликабельна (проект стартовал недавно — таких дней много, это норма);
  - **сегодня до 20:00** → число + бейдж «скоро», некликабельна;
  - **будущее** → приглушена, некликабельна.
- Выходные/праздники — число красным во всех состояниях.
- Текущий выбранный день — видимая рамка/подсветка.
- Листание месяцев ограничено: не раньше первого месяца с выпуском,
  не позже текущего месяца.

### 5.3 Навигация
- Клик по ячейке → отрывной календарь перелистывается на выбранную дату.
- Стрелки ‹ › рядом с листом (и клавиши ←/→): предыдущий/следующий день
  **с выпуском** (пропуская пустые дни).
- Мобильный: свайп влево/вправо по листу = те же переходы.
- **URL-роутинг**: `/{yyyy}/{mm}/{dd}` — прямая ссылка на день;
  `/` — редирект на последний опубликованный выпуск. History API,
  переходы без перезагрузки страницы.
- Открытие ссылки на день без выпуска → мягкая страница «В этот день выпуска
  не было» + ссылка на ближайший выпуск и календарь.

### 5.4 Адаптив
- Desktop (>= 1024px): две зоны рядом.
- Планшет/мобильный: одна колонка — лист сверху, сетка месяца под ним
  (сворачиваемая, кнопка «Календарь»).
- Минимальная поддерживаемая ширина: 360px.

## 6. Выходные и праздники

- Статический файл в репозитории `src/data/holidays-{year}.json` — праздничные
  и перенесённые дни производственного календаря РФ:

```json
{
  "2026": {
    "holidays": ["2026-01-01", "2026-01-02", "2026-02-23"],
    "workdays": []
  }
}
```

- `workdays` — перенесённые рабочие субботы, они НЕ красные.
- Красным считаются: суббота, воскресенье, даты из `holidays`,
  за вычетом дат из `workdays`.
- Файл на следующий год добавляется вручную раз в год (простая операция).
- Опционально (фаза 2): фолбэк на API `isdayoff.ru`, если файла на год нет.

## 7. Крайние случаи

- **Пропущенный день** (картинку не загрузили): сетка показывает ячейку без
  превью, навигация стрелками перескакивает пропуск, сайт не ломается.
- **Проект молодой**: в первый месяц заполнено 1–5 дней — сетка месяца всё
  равно рендерится полностью, пустые ячейки выглядят аккуратно (это витрина
  на годы вперёд, «пустота» первых недель — временное состояние).
- **Много лет данных** (перспектива): список выпусков запрашивается
  **помесячно** (`issue_date` в диапазоне месяца), а не весь архив разом.
- **Ошибка загрузки картинки** (битый файл в Storage): плейсхолдер с логотипом
  вместо разорванной вёрстки, обработчик `onerror` на `<img>`.
- **20:00 и часовые пояса посетителей**: «сегодня» и момент появления выпуска
  определяются по Europe/Moscow независимо от таймзоны браузера.

## 8. SEO и шаринг (минимум, но с первого дня)

- `<title>`: «Пульс дня — 8 августа 2026» (динамически по выбранной дате).
- OG-теги: `og:title`, `og:image` (= `thumb-480`), `og:url`, `og:description`.
  Ограничение SPA: краулеры соцсетей не исполняют JS — для корректных превью
  ссылок использовать пререндер на этапе деплоя (Vercel OG / vite-плагин)
  **или** осознанно отложить на фазу 2 (решение зафиксировать).
- `sitemap.xml` по опубликованным дням — фаза 2.

## 9. Пошаговый план работ (выполнять строго по одному шагу)

| # | Шаг | Результат / критерий приёмки |
|---|-----|------------------------------|
| 1 | **Дизайн-макет через Stitch**: два экрана (desktop, mobile) по структуре §5; стиль — тёплый винтажный отрывной календарь, сочетающийся с иллюстрациями (бумага, перфорация, красные акценты дат) | Макет утверждён заказчиком до начала вёрстки |
| 2 | **Supabase**: бакет `pulse-covers`, таблица `site_issues`, RLS-политики из §3 | Анонимный ключ читает только `published = true`; запись анонимом невозможна |
| 3 | **Доработка бота**: приём картинки, генерация 3 файлов, upsert в Storage и таблицу, поддержка явной даты в подписи | Тестовая картинка боту → в Storage 3 файла по пути `yyyy/mm/dd/`, строка в таблице; повторная отправка перезаписывает |
| 4 | **Публикация в 20:00** в боте + алерт при отсутствии картинки | Флаг `published` ставится в 20:00 МСК; повторный запуск идемпотентен |
| 5 | **Каркас фронта**: Vite + React + TS, роутинг `/{yyyy}/{mm}/{dd}`, запросы к Supabase (anon key), редирект `/` на последний выпуск | Открытие прямого URL показывает данные нужного дня |
| 6 | **Отрывной календарь** (§5.1): лист, красные даты, иллюстрация, лайтбокс | Соответствие макету шага 1 на тестовых данных 3–4 дней |
| 7 | **Сетка месяца** (§5.2): превью, 4 состояния ячеек, листание месяцев, помесячная загрузка данных | Все состояния ячейки корректны; листание ограничено диапазоном выпусков |
| 8 | **Навигация и анимация** (§5.3): клик по ячейке, стрелки, клавиатура, свайп, анимация отрыва листа | Переходы обновляют URL; пропуски дней перескакиваются; `prefers-reduced-motion` учтён |
| 9 | **Праздники** (§6) + адаптив (§5.4) + крайние случаи (§7) | Красные даты соответствуют производственному календарю; сайт корректен на 360px; отсутствующая/битая картинка не ломает вёрстку |
| 10 | **Деплой + SEO-минимум** (§8): Vercel/Netlify, env-переменные, OG-теги, favicon | Продакшн-URL работает; ссылка на день корректно разворачивается в Telegram |
